# ORVIO — Restaurant POS

რესტორნის სალაროს საცდელი პროგრამა: მაგიდები, მენიუს ხელით შეყვანა, შეკვეთები, განყოფილებების ჩეკები, მენეჯერის PIN-ით დაცული ფასდაკლება და მართვა, შერეული გადახდის აღრიცხვა, ანგარიშები.

## ამ ვერსიის გარემო

**Next.js → Vercel → Supabase Auth + PostgreSQL.** GitHub ინახავს კოდსა და ცვლილებების ისტორიას. Vercel გაუშვებს აპს. Supabase ინახავს ანგარიშებსა და შეკვეთებს.

Vercel-ზე გამოქვეყნებამდე საჭიროა Supabase-ის პროექტის გამართვა და გარემოს ცვლადების შევსება. ზუსტი ნაბიჯები: [განთავსების გზამკვლევი](docs/VERCEL.md).

ეს ვერსია შეიცავს დამოუკიდებელ ელფოსტითა და პაროლით შესვლას. Sites-ის წინა ვერსიის ავტორიზაციის სათაურებს აღარ ენდობა. ძველი საცდელი საიტი დამოუკიდებლად აგრძელებს მუშაობას; მისი მონაცემები ახალ ბაზაში ავტომატურად არ გადმოდის.

## ლოკალურად გაშვება

Node.js 22 და `package.json`-ში მითითებული pnpm ვერსია:

```sh
corepack enable
pnpm install --frozen-lockfile
cp .env.example .env.local
# შეავსეთ თქვენი Supabase გარემოს ცვლადები
pnpm dev
```

```sh
pnpm test
pnpm typecheck
pnpm build
```

ყველა თანხა ითვლება მთელ თეთრებში. სწრაფი დაჭერა ამატებს ერთ ერთეულს; რაოდენობისა და შენიშვნის ღილაკი ხსნის ცალკე ფორმას. მენეჯერის PIN პირველივე შესვლისას უნდა შექმნათ — სტანდარტული PIN არ არსებობს.

## საცდელი ვერსიის საზღვრები

საბანკო/ფისკალური ინტეგრაცია და ფიზიკურ პრინტერზე მიწოდების დადასტურება ჯერ არ არის; გამოიყენება ბრაუზერის ბეჭდვის ფანჯარა. საწყობი, თვითღირებულება, თანხის დაბრუნება და ოფლაინ რიგი შემდეგი ეტაპია. ნაწილობრივი გადახდის შემდეგ შეკვეთის რედაქტირება იბლოკება.

თითოეულ დაშვებულ ანგარიშს საკუთარი საცდელი მონაცემები აქვს; ეს ჯერ საერთო რესტორნის თანამშრომელთა როლების სისტემა არ არის. განყოფილების ეკრანი იმავე ანგარიშით მუშაობს. სესიის ვადის გასვლისას საჭიროა ხელახლა შესვლა. შენახული შეკვეთები ბაზაში რჩება.

ერთი დოკუმენტი თითო ანგარიშზე ადრეული პროტოტიპის არჩევანია; დიდი ისტორიისა და რეალური დატვირთვისთვის საჭიროა ცალკე ცხრილები და გვერდებად ჩატვირთვა.
