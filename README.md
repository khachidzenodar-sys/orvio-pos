# ORVIO — Restaurant POS

რესტორნის სალაროს საცდელი პროგრამა: მაგიდები, მენიუს ხელით შეყვანა, შეკვეთები, განყოფილებების ჩეკები, მენეჯერის PIN-ით დაცული ფასდაკლება და მართვა, შერეული გადახდის აღრიცხვა, ანგარიშები.

## ამ ვერსიის გარემო

**Next.js → Vercel.** მთავარი გვერდი იხსნება შესვლის გარეშე, ლოკალური დემო რეჟიმით. თითოეული ბრაუზერი ინახავს თავის საცდელ შეკვეთებს. დემო მენეჯერის საწყისი კოდია **1234**; ის მხოლოდ ფუნქციების გამოსაცდელია.

**`/workspace` → Supabase Auth + PostgreSQL.** ანგარიშით შესვლის რეჟიმი ცალკე მისამართზეა შენარჩუნებული. GitHub ინახავს კოდსა და ცვლილებების ისტორიას, Vercel უშვებს აპს, Supabase კი ანგარიშით შესული მომხმარებლების მონაცემებს ინახავს.

Vercel-ზე გამოქვეყნებამდე საჭიროა Supabase-ის პროექტის გამართვა და გარემოს ცვლადების შევსება. ზუსტი ნაბიჯები: [განთავსების გზამკვლევი](docs/VERCEL.md).

დემოს მონაცემები Supabase-ში არ იგზავნება და სხვა მოწყობილობაზე არ გადადის. იმავე ბრაუზერის განყოფილების ფანჯრები საერთო ლოკალურ ჩანაწერს კითხულობს. ბრაუზერის მონაცემების გასუფთავება ან „დემოს განულება“ საცდელ ისტორიას შლის. რეალური ფინანსური მონაცემებისთვის გამოიყენეთ ანგარიშით შესვლა.

Sites-ის ძველი საცდელი საიტი დამოუკიდებლად აგრძელებს მუშაობას; მისი მონაცემები ახალ ბაზაში ავტომატურად არ გადმოდის.

## ლოკალურად გაშვება

Node.js 22 და `package.json`-ში მითითებული pnpm ვერსია:

```sh
corepack enable
pnpm install --frozen-lockfile
cp .env.example .env.local
# შეავსეთ თქვენი Supabase გარემოს ცვლადები
pnpm dev
```

```sh
pnpm test
pnpm typecheck
pnpm build
```

დემოს გასაშვებად Supabase-ის ცვლადები საჭირო არ არის; ისინი `/workspace` რეჟიმისთვის უნდა შეავსოთ.

ყველა თანხა ითვლება მთელ თეთრებში. სწრაფი დაჭერა ამატებს ერთ ერთეულს; რაოდენობისა და შენიშვნის ღილაკი ხსნის ცალკე ფორმას. ანგარიშით შესვლისას მენეჯერის PIN თავად უნდა შექმნათ — დემოს **1234** ამ ანგარიშზე არ მოქმედებს.

## საცდელი ვერსიის საზღვრები

საბანკო/ფისკალური ინტეგრაცია და ფიზიკურ პრინტერზე მიწოდების დადასტურება ჯერ არ არის; გამოიყენება ბრაუზერის ბეჭდვის ფანჯარა. საწყობი, თვითღირებულება, თანხის დაბრუნება და ოფლაინ რიგი შემდეგი ეტაპია. ნაწილობრივი გადახდის შემდეგ შეკვეთის რედაქტირება იბლოკება.

ანგარიშით შესვლის რეჟიმში თითოეულ დაშვებულ ანგარიშს საკუთარი საცდელი მონაცემები აქვს; ეს ჯერ საერთო რესტორნის თანამშრომელთა როლების სისტემა არ არის. განყოფილების ეკრანი იმავე ანგარიშით მუშაობს. სესიის ვადის გასვლისას საჭიროა ხელახლა შესვლა. შენახული შეკვეთები ბაზაში რჩება.

ერთი დოკუმენტი თითო ანგარიშზე ადრეული პროტოტიპის არჩევანია; დიდი ისტორიისა და რეალური დატვირთვისთვის საჭიროა ცალკე ცხრილები და გვერდებად ჩატვირთვა.
