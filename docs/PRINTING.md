# ბეჭდვა თერმულ პრინტერზე (Windows აპი)

ეს დოკუმენტი აღწერს, როგორ დაუკავშიროთ ORVIO-ს Windows აპს 80 მმ-იანი თერმული ჩეკის პრინტერი (ESC/POS) და რა გააკეთოთ, თუ ბეჭდვა არ მუშაობს.

ბეჭდვა ორი სახისაა:

- **სტუმრის ჩეკი** — ღილაკი „ჩეკი / ბეჭდვა“.
- **განყოფილების ჩეკი** (სამზარეულო, ბარი) — შეკვეთის გაგზავნისას და ხელახალი ბეჭდვისას.

## 1. პრინტერის დაყენება Windows-ში

1. შეაერთეთ პრინტერი კომპიუტერთან (USB, ქსელი ან Bluetooth) და ჩართეთ.
2. დააყენეთ მწარმოებლის Windows დრაივერი (მაგალითად, XPrinter, Epson TM, Rongta). დრაივერი ჩვეულებრივ პრინტერთან ერთად მოდის ან მწარმოებლის საიტზეა.
3. გახსენით **Settings → Bluetooth & devices → Printers & scanners** და დარწმუნდით, რომ პრინტერი სიაშია.
4. სურვილისამებრ Windows-იდან გააკეთეთ „Print test page“, რომ დრაივერი შეამოწმოთ.

„Generic / Text Only“ დრაივერი **საჭირო არ არის**. ORVIO პრინტერს მონაცემს RAW სახით უგზავნის: Windows მას არ ცვლის და პირდაპირ პრინტერს გადასცემს. ამიტომ ნებისმიერი დრაივერი გამოდგება, რომელიც პრინტერს Windows-ის სიაში აჩენს.

## 2. პრინტერის არჩევა ORVIO-ში

1. გახსენით ORVIO და გადადით **მართვა → პრინტერი**.
2. სიიდან აირჩიეთ თქვენი თერმული პრინტერი. თუ ახლახან დააყენეთ და სიაში არ ჩანს, დააჭირეთ სიის განახლებას.
3. დააჭირეთ **„საცდელი ბეჭდვა“**. უნდა დაიბეჭდოს საცდელი ჩეკი: სათაური, თარიღი, ქართული ტექსტი, `₾ 12.50` და ზოლი `|< 80 მმ … >|`.
4. შეამოწმეთ საცდელი ჩეკი:
   - ქართული ასოები სწორად და მკაფიოდ იკითხება;
   - `|<` და `>|` ნიშნები ქაღალდის ორივე კიდესთან ჩანს და არ იჭრება;
   - ჩეკის ბოლოს ქაღალდი იჭრება (თუ პრინტერს საჭრელი აქვს).

არჩეული პრინტერი ინახება კომპიუტერზე და აპის ხელახლა გახსნისას აღარ იკითხება.

თუ პრინტერი არ არის არჩეული, ORVIO ძველებურად იყენებს ბეჭდვის ფანჯარას (ისევე, როგორც ბრაუზერის ვერსია).

## 3. როცა არაფერი იბეჭდება

ბეჭდვის შეცდომისას ORVIO აჩვენებს ფანჯარას შეცდომის ტექსტით და ორი არჩევანით:

- **„თავიდან ცდა“** — იგივე ჩეკი იგზავნება ხელახლა. ჩეკი მეორედ არ ითვლება.
- **„ბეჭდვის ფანჯრიდან“** — ჩეკი იბეჭდება Windows-ის ბეჭდვის ფანჯრით.

ხშირი მიზეზები:

| შეტყობინება | რა უნდა გააკეთოთ |
| --- | --- |
| „პრინტერი გათიშულია ან მზად არ არის“ | ჩართეთ პრინტერი, შეამოწმეთ კაბელი, ქაღალდი და სახურავი. Windows-ში მოხსენით „Use Printer Offline“, თუ მონიშნულია. |
| „პრინტერი „…“ ვერ მოიძებნა“ | პრინტერი წაიშალა ან სახელი შეიცვალა. **მართვა → პრინტერი**-ში ხელახლა აირჩიეთ. |
| „ჯერ აირჩიეთ პრინტერი“ | საცდელი ბეჭდვისთვის ჯერ აირჩიეთ პრინტერი სიიდან. |
| ჩეკი ქაღალდზე არ გამოდის, შეცდომა კი არ ჩანს | შეამოწმეთ, რომ არჩეულია თერმული პრინტერი და არა სხვა (მაგ. „Microsoft Print to PDF“). გახსენით Windows-ის ბეჭდვის რიგი და წაშალეთ გაჭედილი დავალებები. |
| ქაღალდზე უცნაური სიმბოლოები იბეჭდება | პრინტერი ESC/POS ბრძანებებს არ იგებს. ORVIO-ს სჭირდება ESC/POS-თავსებადი თერმული პრინტერი. |
| ჩეკის კიდე იჭრება ან ტექსტი ძალიან ვიწროა | პრინტერი 80 მმ-იანი არ არის (მაგ. 58 მმ-იანია). იხილეთ მე-4 ნაწილი. |

შეცდომის ტექსტის ბოლოს ფრჩხილებში შეიძლება ეწეროს Windows-ის შეცდომის კოდი. ტექნიკური დახმარებისთვის ეს კოდი სასარგებლოა.

## 4. რატომ იბეჭდება ჩეკი სურათად

თერმული პრინტერების უმეტესობამ ქართული ანბანი არ იცის. ტექსტად გაგზავნილ ქართულ ასოებს ასეთი პრინტერი უცნაურ სიმბოლოებად ბეჭდავს. ამიტომ ORVIO ჩეკს ჯერ შავ-თეთრ **სურათად** ხატავს Noto Sans Georgian შრიფტით (შრიფტი აპშია ჩაშენებული, ინტერნეტი არ სჭირდება) და პრინტერს სურათს უგზავნის. სურათის ბეჭდვა (ESC/POS `GS v 0` ბრძანება) ყველა ESC/POS თერმულ პრინტერს შეუძლია, ამიტომ ქართული ტექსტი და `₾` ნიშანი ყოველთვის სწორად გამოჩნდება.

სიგანე: 80 მმ-იან ქაღალდზე ბეჭდვის არე დაახლოებით 72 მმ-ია. 203 dpi გარჩევადობით ეს **576 წერტილია**. ORVIO სურათს ზუსტად 576 წერტილის სიგანით ხატავს, გვერდებზე 8 წერტილის დაშორებით. 58 მმ-იანი პრინტერი (384 წერტილი) ამ სიგანეს ვერ დაიტევს და მხარდაჭერილი არ არის.

## 5. ტექნიკური დეტალები (დეველოპერისთვის)

```
PrintDocument → receipt-layout (Row[]) → canvas-renderer (576 px) → bitmap (1 bit)
  → escpos: ESC @ + GS v 0 ზოლები (≤ 255 სტრიქონი, xL = 72) + ESC d 4 + GS V 66 0
  → invoke('print_raw', {printer, data}) → Rust: winspool RAW
```

| ფაილი | როლი |
| --- | --- |
| `lib/ports/printer.ts` | პორტები: `ReceiptPrinter`, `PrinterSettings`, `Bitmap` |
| `lib/printing/receipt-layout.ts` | ჩეკის შინაარსი სტრიქონებად (`Row[]`), სუფთა ფუნქციები |
| `lib/printing/day-report-layout.ts` | დღის ანგარიში სტრიქონებად: `dayReportRows` |
| `components/rows-print.tsx` | ბრაუზერის ბეჭდვა: იგივე `Row[]` HTML-ად |
| `lib/printing/canvas-renderer.ts` | სტრიქონების დახატვა 576 px სიგანის canvas-ზე |
| `lib/printing/bitmap.ts` | RGBA → 1-ბიტიანი bitmap (ზღვარი 160) |
| `lib/printing/escpos.ts` | ESC/POS ბაიტები |
| `lib/adapters/escpos-printer.ts` | დესკტოპის პრინტერი: არჩეული პრინტერი (`orvio.printer.v1`), ბეჭდვა, საცდელი ბეჭდვა |
| `lib/adapters/browser-printer.ts` | ბრაუზერი: ყოველთვის ბეჭდვის ფანჯარა |
| `src-tauri/src/printer/mod.rs` | Tauri ბრძანებები `list_printers`, `print_raw` (`spawn_blocking`-ში) |
| `src-tauri/src/printer/windows.rs` | winspool: `EnumPrintersW`, `OpenPrinterW`, `GetPrinterW` (მდგომარეობა), `StartDocPrinterW` „RAW“, `WritePrinter` |
| `src-tauri/src/printer/stub.rs` | სხვა სისტემებზე: ცარიელი სია და გასაგები შეცდომა |

**დღის ანგარიში.** „ანგარიშები → დღის ანგარიში“-ში ღილაკი „ბეჭდვა“ ქმნის `dayReportRows(...)`-ს და აგზავნის დოკუმენტს `{kind: 'rows', rows}`. ESC/POS ადაპტერი ამ სტრიქონებს პირდაპირ ხატავს (იგივე 576 წერტილის გზით, რაც ჩეკი), ბრაუზერში კი `RowsPrint` იგივე სტრიქონებს ბეჭდვის დიალოგში აჩვენებს. ცოცხალ ანგარიშზე „დათვლილი“ და „სხვაობა“ ყოველთვის იბეჭდება როგორც „—“ (ეკრანზე აკრეფილი თანხა ჯერ შენახული არ არის); ეს რიცხვები იბეჭდება შენახული დახურვიდან. შენახული დახურვის ბეჭდვა (ისტორიიდან) იყენებს ჩანაწერის ასლს და ბეჭდავს „დღის დახურვა #1“ ან „განმეორებითი დახურვა #N“, ვინ დახურა და შენიშვნას.

Rust ბეჭდვამდე ამოწმებს პრინტერის მდგომარეობას (`GetPrinterW` level 6 და 4): offline, error, not available, paper out ან „Use Printer Offline“ → „პრინტერი გათიშულია ან მზად არ არის“. ზოგიერთი USB დრაივერი მდგომარეობას სწორად არ აცნობებს. ასეთ შემთხვევაში დავალება რიგში ჩადგება და პრინტერის ჩართვისას დაიბეჭდება.

Linux კონტეინერში შემოწმდა კოდი და ტესტები (`tests/escpos.test.ts`, `tests/bitmap.test.ts`, `tests/receipt-layout.test.mjs`, `tests/escpos-printer.test.mjs`, `tests/day-report-layout.test.mjs`, `cargo check --target x86_64-pc-windows-msvc`). ფიზიკური ბეჭდვა, ჭრა და ქართული ასოების ხარისხი ქაღალდზე მოწმდება მხოლოდ ნამდვილ Windows კომპიუტერზე, საცდელი ბეჭდვით.
