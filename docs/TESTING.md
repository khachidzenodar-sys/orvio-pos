# შემოწმება

გაუშვით `npm test`, `npm run typecheck` და `npm run build`.

ტესტები მოიცავს ფასებს, ფასდაკლებას, შერეულ გადახდებს, განმეორებითი მოთხოვნების დაცვას, ვერსიების შეჯახებას, მენეჯერის PIN-ს, სწრაფ დაჭერებს, სესიას, მომხმარებელთა იზოლაციასა და Supabase HTTP კონტრაქტებს.

`tests/demo.test.mjs` დამატებით ამოწმებს დემოს ლოკალურ შენახვას, გვერდის განახლების მოდელირებას, დამოუკიდებელი ბრაუზერების იზოლაციას, ქსელის გამოუყენებლობას, სწრაფ დამატებას, განყოფილებების ჩეკებს, საცდელ PIN-ს, ფასდაკლებასა და გადახდას, პარალელურ ფანჯრებს, განულების შემდეგ ძველი მოქმედების უარყოფასა და მიუწვდომელ/დაზიანებულ საცავს.

`tests/addons.test.ts` ამოწმებს სწრაფ შენიშვნებსა და ფასიან დანამატებს: კატალოგიდან აღებულ ფასს, რაოდენობაზე გამრავლებას, ვარიანტების დაჯგუფებას, ისტორიული ფასების/სახელების შენარჩუნებას, რამდენიმე განყოფილებაში გაგზავნასა და გაუქმებას, ფასდაკლებასა და გაყოფილ გადახდას. API-ისა და დემოს ტესტებში დამატებულია ფასის გაყალბების უარყოფისა და ახალი/ძველი შენახული მონაცემების თავსებადობის სცენარები.

`tests/receipt-options.test.mjs` ამოწმებს რეალურად დარენდერებულ დანამატების დეტალებს: სალაროსთვის ფასებით, სამზარეულოსთვის ფასების გარეშე, ძველი პოზიციების მხარდაჭერასა და ტექსტის უსაფრთხო გამოტანას.

დღის ანგარიში და მაგიდების რუკა:

| ფაილი | რას ამოწმებს |
| --- | --- |
| `tests/day-report.test.ts` | საცნობარო დღის ჯამები, ცარიელი დღე, თბილისის შუაღამის საზღვარი, სალაროს სხვაობა, თანხის შეყვანა, `closeDay` (შეკვეთები უცვლელია, განმეორებითი დახურვა) |

| `tests/floor-plan-persistence.test.mjs` | `saveFloorPlan` დემოში და route-ში, `layout`-ის მკაცრი შემოწმება, ძველი დოკუმენტი, სარეზერვო ასლი |

`pos.ts`-ის ჩამტვირთავი `.mjs` ტესტები იყენებენ საერთო `tests/helpers/load-domain.mjs`-ს.

Supabase ქსელური პასუხები ტესტებში ჩანაცვლებულია. რეალურ ბაზაზე სქემის, ნებართვებისა და ავტორიზაციის შემოწმება საჭიროა დაკავშირების შემდეგ. ავტომატური ტესტები და TypeScript-ის შემოწმება არ ცვლის გამოქვეყნებულ აპლიკაციაში პროცესის გავლას.

ცოცხალი შემოწმების ნაბიჯები იხილეთ [განთავსების გზამკვლევში](VERCEL.md).
