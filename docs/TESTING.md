# შემოწმება

გაუშვით `npm test`, `npm run typecheck` და `npm run build`.

ტესტები მოიცავს ფასებს, ფასდაკლებას, შერეულ გადახდებს, განმეორებითი მოთხოვნების დაცვას, ვერსიების შეჯახებას, მენეჯერის PIN-ს, სწრაფ დაჭერებს, სესიას, მომხმარებელთა იზოლაციასა და Supabase HTTP კონტრაქტებს.

`tests/demo.test.mjs` დამატებით ამოწმებს დემოს ლოკალურ შენახვას, გვერდის განახლების მოდელირებას, დამოუკიდებელი ბრაუზერების იზოლაციას, ქსელის გამოუყენებლობას, სწრაფ დამატებას, განყოფილებების ჩეკებს, საცდელ PIN-ს, ფასდაკლებასა და გადახდას, პარალელურ ფანჯრებს, განულების შემდეგ ძველი მოქმედების უარყოფასა და მიუწვდომელ/დაზიანებულ საცავს.

Supabase ქსელური პასუხები ტესტებში ჩანაცვლებულია. რეალურ ბაზაზე სქემის, ნებართვებისა და ავტორიზაციის შემოწმება საჭიროა დაკავშირების შემდეგ. ავტომატური ტესტები და TypeScript-ის შემოწმება არ ცვლის გამოქვეყნებულ აპლიკაციაში პროცესის გავლას.

ცოცხალი შემოწმების ნაბიჯები იხილეთ [განთავსების გზამკვლევში](VERCEL.md).
